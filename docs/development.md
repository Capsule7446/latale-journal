# 前端开发约定

定稿日期：2026-11-08。本文落实用户确认的纯前端、PWA、Cloudflare、独立资料更新及固定代码解析要求；实现状态以 README 和具体任务验收为准。

## 已定边界

1. **纯前端**：通过静态 JSON 和图片完成搜索、筛选、分页、详情及关联跳转。线上不依赖 Go/Bun 查询 API、动态业务函数、数据库服务或开发者电脑。
2. **PWA**：支持手机与电脑安装；首版页面和已访问资料可离线，未缓存资料提示联网。全库下载不属于首版要求，缓存容量与淘汰方式在实现时测量确定。
3. **Cloudflare**：应用构建产物静态托管，资料使用独立发布入口。Workers Static Assets、Pages、R2 等具体产品配置仍按部署任务定案，不把建议写成已开通或已部署。
4. **数据契约由前端维护**：在已验证资料能力和已确认需求基础上定义 JSON 结构，由资料仓库按固定版本生成；兼容格式的资料更新无需修改、重建或重新发布前端。
5. **AI 不进入资料生产运行链**：AI 可辅助开发和审查程序；解析、补值、转换、校验、打包由资料仓库的固定代码完成。前端不直接读取游戏档案，也不对缺失内容调用 AI 推断。

## 功能开发流程

1. **核验输入能力**：读取本板块规格，让资料仓库的固定程序提供字段、关系、单位和全量覆盖证据；未证能力保留具体阻塞，不能用样例或原表存在代替通过。
2. **确定契约**：按 [数据契约协作](data-contract.md)定义字段、身份、单位、缺失、关系、索引和版本；提供机器可验的 Schema、有效/无效样本及前端类型。
3. **生成真实静态包**：资料仓库按该契约生成版本化 JSON；应用开发使用同结构的真实产物，界面样例不得冒充全量查询。
4. **开发并预览**：沿用已确认的界面与交互，开发服务只托管静态数据并提供热更新。正式代码不依赖相邻仓库路径，数据根地址由开发/部署配置提供。
5. **验收**：在业务查询 API 不可达时核对搜索、计数、详情、关系和返回状态；生产构建验证安装、断网、资料更新及应用更新。完成后将命令和验收证据写回 README 与任务。

## 数据与缓存规则

1. 应用版本、格式版本和资料版本分别管理。一次读取固定同一资料版本；新版本准备成功后整体切换，失败保留旧版。
2. 数据以运行时静态请求加载，不把全库 JSON 或当前资料版本编译进 JS bundle。搜索索引覆盖已确认的查询范围，不能只筛选当前下载的一页。
3. 版本内容不可变，当前版本入口可重新验证；数据更新与 Service Worker/应用更新分开处理。缓存清空或存储不足时提供联网恢复途径。
4. 离线浏览使用已缓存资料；离线搜索说明可用范围，不把缓存子集当成全库。未缓存、无匹配、未知字段、请求失败和实体已移除分别处理。
5. 业务 ID 与实体类型共同确定身份；保留单位、零值、空集合和未知的区别。已确认的取消/暂缓范围不因迁移而恢复；跨版本移除的对象不能改跳同名对象。

## 完成标准

| 变更 | 必须验证 |
| --- | --- |
| 新板块或数据结构 | 固定解析证据、契约校验、全量查询覆盖、静态读取与真实关系跳转 |
| 界面交互 | 已确认行为、加载/错误/空态、手机窄屏、键盘与浏览器历史 |
| PWA | 支持设备的安装路径、独立启动、已访问资料离线、未缓存提示、更新与恢复 |
| 资料兼容 | 同一份应用构建可切换两份兼容资料包，应用文件无需改变 |
| 应用发布 | 可复现构建、Cloudflare 预览、静态读取、缓存兼容和回退 |

安装兼容依据见 [MDN PWA 安装说明](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)。发布凭据由维护端/CI 管理，不进入前端产物。首次实现从一条真实资料的静态查询链开始，再按已确认板块扩展；首条链通过不代表全站完成。
