# 两仓库的数据契约协作

本仓库的 `contracts/` 是 JSON 契约的唯一维护来源；`latale-wiki-data` 是实现该契约的数据生产者。契约描述前端需要的已验证资料含义，不把原始游戏表结构直接暴露为页面接口。

## 所有权与传递

1. **定义**：前端仓库维护格式版本、JSON Schema、字段含义、索引规则、样本及兼容性约束；资料仓库反馈可解析性和覆盖范围。
2. **冻结**：契约通过生产者与消费者校验后发布可校验的契约包，记录来源提交及内容 SHA-256。可读版本标签只作定位，不能用可移动分支代替内容身份。
3. **消费**：资料仓库锁定包版本、来源提交和哈希；通过显式依赖或可审计的只读快照取得契约，不维护另一套手写 Schema。运行时不要求本仓库同时检出。
4. **升级**：兼容增加需验证旧消费者可用；破坏字段含义或结构时使用新格式入口，先准备支持该格式的前端，再切换资料。旧 PWA 保留可用的旧格式入口与资料。
5. **验证**：两仓库使用同一契约身份。资料仓库验证生成文件；前端验证版本、必需数据和加载结果。失败停止发布或切换，不能回退到 AI 补齐字段。

## 首次契约必须覆盖

| 类别 | 必须明确 |
| --- | --- |
| 身份与语义 | 实体类型、业务 ID、关系方向、单位、未知/零/空集合、缺失引用 |
| 查询 | 已确认搜索字段、筛选与组合、全量索引范围、去重与稳定排序 |
| 分片 | 目录与详情定位、资源地址、大小和内容哈希、按需加载边界 |
| 版本 | 格式版本、资料版本、不可变清单、按格式区分的当前版本入口 |
| 验收 | 合法与非法样本、引用检查、计数、兼容性和同输入复现 |

当前首份基础道具格式见 [items-v1](../contracts/items-v1/README.md)，包含机器 Schema、两侧共用校验器及生成类型。精确来源提交与内容身份由消费锁记录；该格式只覆盖已证基础字段，不表示完整领域资料已接入。
