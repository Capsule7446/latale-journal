# 本仓库任务与规格

创建、读取或更新任务前阅读本文件。本仓库独立维护工作记录，不写回父工作区的 `chd-records/.scratch/`。

- 每个功能在 `.scratch/<feature>/spec.md` 保存一份规格；已确认、建议和未决事项分开。
- 实施任务放 `.scratch/<feature>/issues/<NN>-<slug>.md`，一项一文件，写清范围、依赖和验收。
- 跨仓库任务分别放在所属仓库，记录对方任务标识与契约版本，不假定有共享 Git 历史或相邻检出路径。
- 固定资料核验报告记录真实输入身份与机器结果；大数据、原始资源、日志和密钥不提交。文档链接不能指向被忽略且没有获取说明的产物。
- 本次只建立定义与规范，不自动把后续实施任务标为完成；进入实现前补充可执行任务。

分诊状态沿用 `needs-triage`、`needs-info`、`ready-for-agent`、`ready-for-human`、`wontfix`，分别表示待评估、待信息、可由代理执行、需人工执行、不处理。状态写在任务的 `Status:` 行，讨论追加到 `Comments`。
