# 01：按编号读取真实静态道具详情

Status: ready-for-agent

Work: complete

Feature: `feature/static-items/item-detail`

Blocked by: None。基础字段能力、冻结契约及固定出口已提供，随 [任务 04](04-data-only-preview.md) 在 `feature/static-items/page-style` 完成本任务最小切片。

## 交付

用户输入一个真实道具编号，可通过纯静态文件读取该道具的编号、名称、已证分类路径和原说明；缺说明、未知分类、编号不存在、网络失败与格式不兼容分别处理。这是首条最小切片，完整要求仍见 [道具规格](../spec.md)。

## 实施顺序

1. 读取资料仓库的能力报告，选取已证字段；在本仓库定义最小版本清单、道具身份与详情契约，补充合法／非法样本及校验。不能将待证字段猜成必需字段。
2. 冻结契约的版本、来源提交和 SHA-256，供生产者消费。字段命名和分片方式以实际能力与大小确定，不从旧 API 结构直接抄成最终 JSON。
3. 资料仓库使用同一身份导出真实静态包后，以可配置数据根地址加载。仓库单独检出可构建，不依赖父目录、相邻源码或查询 API。
4. 沿用已确认布局的基础区域完成读取、错误和返回；首条切片不显示未实现的筛选或虚构详情。
5. 用同一生产构建与真实包验收，记录命令、包身份、范围及未覆盖项；将 CI 扩充为真实契约校验、应用检查和构建后再报告通过。

## 验收

- [x] 固定生产者生成多个真实编号的详情及清单，不由 AI 或人工手填正式资料；输入及契约身份可追溯。
- [x] 不依赖业务查询 API 时可精确读取 `84905009`；不存在编号返回明确不存在，不能跳同名对象。
- [x] 已证分类显示完整路径，未知分类／缺原说明不补造；内容来自所选编号，不继承其他强化版本。
- [x] 清单与详情版本一致；必需文件缺失、格式不支持或内容损坏时失败并保留可恢复状态。
- [x] 320px 与桌面可读，返回和失败重试有效；README 给出从单独检出到静态预览的实际可执行命令。

## 不计入完成

全量搜索、默认初始形态过滤、全部品类详情、关系页、PWA 安装／离线、Cloudflare 上线及游戏资源导入均由后续明确任务验收。首条页面成功不能关闭整个 epic；使用既有 SQLite 时如实标记后半段验证。
