# 03：途径默认折叠，同途径展开多个方案

Status: ready-for-agent

Work: completed

Feature: `feature/static-items/page-style`（继续当前样式 feature）

Blocked by: None。样式可用明确标注的演示资料立即实现；真实途径字段由资料仓库的 `static-items/02-route-rule-evidence` 核验，正式资料接入另受契约门槛约束。

## 用户要求与边界

2026-11-09 用户要求材料用途、制作等途径默认收起，外层有途径描述；同一途径名称下的多种材料方案合为一个入口，展开后各自呈现。明确格式与分组语义已写入 [道具规格](../spec.md) 的“途径折叠与多方案”。严格使用用户给出的生活技能示例 `[吉恩蒂亚成品][Lv1]成品制造 > 拳套` 作视觉案例，不能声称它已由真实解析产生。

本会话独占本仓库的实现、样例、测试及任务结果；不改资料仓库，不派生其他会话或代理，不回滚其他协作者的改动。先读取本仓库 AGENTS 和相关源文件。协调会话已经更新规格，此后不与本会话同时修改实现文件。

## 实施与验收

1. 把获取／用途中的配方卡片改为默认折叠的途径组。五种外层描述分别含 NPC、生活技能名／等级／分类路径、分解输入或升级主输入；缺身份时有诚实降级，不能猜字段。
2. 在当前道具和关系方向内按明确身份分组，再做关系列表分页。同 NPC 的两种兑换材料方案仅一个外层入口；不同 NPC 即使同名也不混组，购买／兑换、获取／用途不互串。
3. 展开后独立保留每份方案及真实引用语义，至少演示两种兑换材料方案；费用未知与零、材料数量和不同产物均不被压平。材料追查返回恢复展开、页码及焦点。
4. 覆盖键盘展开／收起、320px 和桌面、默认折叠、五种标签、同源多方案、不误合并和返回恢复。增加有意义的规则／浏览器回归，不写只镜像 DOM 结构的测试。
5. 更新预览验收记录、截图及本任务，运行 CI 与浏览器验收，提交并推送当前 feature。保留 `http://127.0.0.1:4173/` 可预览，不合 master、不发布生产版本。

## 验收结果（2026-11-09）

- [x] 获取方式、材料用途及用途中的途径首次默认折叠，五种外层描述按明示字段显示；生活技能例子完整保留 `[吉恩蒂亚成品][Lv1]成品制造 > 拳套`。
- [x] `91000005` 的 7 份用途方案先分成 6 个途径组再分页，正常预览只有一条 `[兑换]阿洛`，内含两份非相邻兑换方案；同名不同 NPC 与身份缺失反例移入规则测试和浏览器拦截响应，购买／兑换与获取／用途亦不误合并。
- [x] 各方案独立保留材料数量、不同产物、费用 `0` 与未知 `-`、办理地点和条件；页内返回、浏览器后退及刷新恢复展开与关系页码，返回恢复滚动和材料链接焦点。
