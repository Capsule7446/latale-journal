Blocked by: None。本任务使用明确标注的静态演示资料验证样式，不等待真实解析或正式 JSON 契约；真实资料接入仍由 [01](01-static-item-detail.md) 的依赖门槛控制。

## 用户授权与交付

2026-11-08 用户要求两个独立子会话：数据侧确认解析规则，显示侧处理页面样式。本任务交付新前端仓库内可运行、可预览的道具页面样式，包含桌面／手机布局与主要状态；实际修改代码并验收，不只提交建议。

业务和交互以 [道具规格](../spec.md) 为准。沿用已确认布局、五品类主标签、自然滚动、外观和密度选项；完善组件、间距、字体、颜色和响应式表现，不重新发明已确认的查询含义或恢复取消项。

## 所有权与协作

本会话只写 `latale-journal`，旧前端设计目录及其他仓库只读。数据会话在 `latale-wiki-data` 同时工作，不回滚他人修改，不修改其分支或文件；不再创建子会话或派发其他代理。当前分支已由协调会话创建，可直接继续使用。

开始前读取本仓库 AGENTS 及其要求的开发、迁移、领域和分支文档。旧组件定位于旧工作区的 `latale-wiki-frontend/design/shadcn-component-preview/`；读取实际代码及批准记录后按需迁入，不把旧 Bun／Go 查询服务带到新前端，也不改动旧预览。

演示资料与真实生产资料分开，页面清楚标明演示状态；不得把手填样例或缓存子集称为全库查询。只做页面需要的展示模型，不擅自冻结生产契约，不将资料解析规则放入组件。需要新字段时记录展示需求及待对接项，交由后续契约协作处理。

## 实施范围

1. 建立可单独检出的前端运行与构建入口，复用已确认技术与视觉基础，给出确定的本地预览命令和地址。启动服务前检查端口占用，不停止其他会话服务。
2. 实现道具列表、分类／搜索条件区域及五品类详情样式。普通与觉醒初始形态、强化版本和觉醒候选阶段分别表达，不改变规格中的筛选默认值和组合规则。
3. 以有限静态演示数据覆盖长名称、多层路径、不同单位、缺失值、加载、失败、空结果以及窄屏详情返回；演示数据只支持视觉与交互验证。
4. 实际检查至少 320px、手机常用宽度和桌面分栏，验证浅／深外观、键盘焦点、44px 触控目标及页面无横向溢出；用浏览器和截图留证，不仅运行构建。
5. 更新 README 与本任务的命令、预览地址、已验收状态和未对接范围；扩充 CI 至实际前端检查和构建，完成后提交并推送本 feature。不要合 master、发布 Release 或部署生产环境。
